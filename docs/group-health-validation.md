# 群健康调度验证

> 本文保留上一轮健康缓存与混合 CLI 测试的原始结果。当时的报数快速通道现已取消，所有调度入口服从设置；这里的延迟不是新版性能承诺。最新行为与验证见 [按配置决策验收](group-policy-validation.md)。


2026-09-23，针对开发版混合本地 CLI / 云端 Agent 群的报数中断问题。

## 实际故障与修复

原群的运行日志显示：Grok 作为协调人超时，随后 OpenClaw 因缺少模型认证失败；切换到 Gemini 后，执行阶段再次派发给 OpenClaw，其空回复错误被一律解释为外部操作结果不明，整个群任务被中止。

现在的执行规则：

- 每个账号、每个群分别持久化健康结果、配置指纹和响应耗时。默认健康缓存 300 秒，设置中可选 30–3600 秒。不可用成员按配置周期在新任务到来时复查，只有检测成功后恢复；未知成员最早 30 秒后复查。
- 并发 ping 整批最多等待 6 秒，不再逐个等待超时后寻找 Leader。首次探测慢的成员标记为未知；已经失败的成员不能仅因再次超时就恢复可用。
- 新任务按健康、角色与技能匹配、响应速度选择 Leader；上下文续问保持健康的原协调人。执行结果持续修正缓存，负责人失败时重新选择接替者。
- 报数每人一格，健康快成员优先，无额外主持回合和总结；不可用成员发出调度通知后跳过，不能由别人代报。云端报数使用独立且无工具的会话。
- 必需交付可以找匹配的替补。认证失败和未开始执行的排队超时不再误报为外部操作结果不明。确实无法确认外部操作结果的本地中断仍需核对，不自动重复执行。
- 群内排队最多等 6 秒，过期任务以后也不会补执行。报数回复总预算 15 秒，协调人规划 20 秒，普通群回复 120 秒；短回复重试不重置预算。

健康探测衡量的是当时的可响应性，不保证后续任务成功。本地探测调用 CLI 的隔离临时会话并要求只返回 PONG；没有声明所有本地 CLI 都具备统一的工具禁用协议。

## 验证方法

自动测试覆盖缓存命中/过期/配置变更、故障恢复、取消、迟到响应、按账号与群隔离、能力和速度排序、串行/并行跳过、Leader 接管、必需交付替补、排队过期不补执行，以及已有群协作与游戏规则回归。

真实测试使用开发版配置复制出的 8 个合成联系人：Grok、OpenClaw、Gemini、Codex、OpenCode、Cursor、DeepSeek、mimo。供应商凭据只在进程内读取；数据库与群聊独立，不修改原联系人和对话。截图中的内置 Dr. Dou 不包含在这次 8 人混合配置测试中。

测试脚本：`scripts/group-health-scenarios.ts`。前两轮是真实探测和真实回复；第三轮注入“探测成功后 Leader 断线”，其余成员仍调用真实模型。办公场景注入 OpenClaw 的过期健康结果，随后使用它真实的认证失败与真实替补模型，验证必需交付能继续。

## 结果

最终全量检查：**535 项通过、4 项按原配置跳过**；70 个测试文件通过、1 个跳过。`npm run typecheck`、`npm test -- --maxWorkers=4`、`npm run build`、`git diff --check` 均通过。还覆盖了成员探测认证失败不能污染独立决策服务的熔断状态。

四个真实混合群场景均通过：

| 场景 | 首条 Agent 回复 | 整轮完成 | 结果 |
| --- | --- | --- | --- |
| 冷启动 8 人报数 | 6.9 秒 | 78.4 秒 | 3 名响应，5 名故障/超时通报后跳过 |
| 缓存后的第二轮报数 | 7.2 秒 | 11.8 秒 | 只重探 2 名到期故障成员，3 名响应 |
| Leader 在探测后断线 | 0.7 秒 | 3.3 秒 | 切换到 mimo，其他可用成员继续 |
| 必需的办公交付 | 16.0 秒 | 16.0 秒 | OpenClaw 失败后 DeepSeek 提交三条技术建议 |

前一批次还观察到了 Grok、Gemini 从失败缓存恢复后正常报数，说明故障状态并非永久排除。冷启动的总耗时仍较长：慢成员首次实际发言各有 15 秒期限；本次改动解决首条回复和持续推进，不声称所有本地程序都能即时响应。OpenClaw 的账号认证配置没有被自动修改。

耗时是本机和当时供应商的观测值，不能作为服务延迟保证。冷启动较慢的本地成员仍可能达到单次回复期限，但会被通报和跳过，不阻止后续成员继续。
