# 按配置决策的群调度验收

本轮针对“设置里的决策方式必须控制实际调度”修改桌面本地群。范围是一个账号、自己的多个 agent，真人参与部分通过消息 API 脚本模拟。

## 行为约定

- 默认：由群成员的隔离协调会话做决策。健康和能力排序只决定先询问哪个协调成员，返回的计划决定实际 leader、执行成员和顺序。
- 决策模型：使用保存的供应商及模型。普通模型走聊天补全；`~typesafe/jev-latest` 等 Jev 模型走 System One。旧 `llm` / `jev` 设置兼容迁移，协议由模型 ID 判断。
- 报数、单人 @、后续交接、成员故障和 leader 故障均经过所选决策方式。Jev 需要完整计划或判断不确定、服务不可用时，明确记录回退到成员协调的原因。
- 任务保存决策配置快照，恢复时继续使用；设置修改从下一个任务生效。
- 故障决策只处理失败步骤：个人报数可跳过，必需交付可替补，无安全方案则暂停。个人发言不能由替补冒充，必需交付不能静默跳过。
- 云端故障决策只返回处理动作、leader、替补三个字段，执行器保留完成记录和剩余计划。已处理的故障不会再额外触发一次协调。
- 完整多人协作计划不会因 `addressedMemberId` 字段而丢失后续参与人。需真人确认时仍先等待确认，再继续完整任务。
- 成员使用自己的模型回复；健康缓存、执行权限、私信隔离、超时和不确定外部操作暂停是所有模式共同的执行约束。

## 自动化验证

回归测试覆盖三个配置路径的首次调度、拒绝回复、显式 @、故障决策、实际 leader 与速度排序不一致时仍服从模型、配置快照、leader 接管后的日志恢复，以及不重复已完成交付。传输测试验证普通模型与 Jev 的端点和故障决策格式；设置组件验证旧配置、普通模型及 Jev 的展示和保存。

真实调用使用 `scripts/group-policy-scenarios.ts`。读取开发版已有 OpenRouter 凭据到内存，在独立数据库创建测试 agent / 群，不修改现有联系人、聊天或模型设置。回复模型为 `xiaomi/mimo-v2.5`；分别使用默认、同一普通 LLM 决策、`~typesafe/jev-latest` 决策。

每种模式运行：

1. 按顺序报数，注入协调员在探测后的回复故障，检查重新选 leader、故障成员跳过、其余成员按序完成。
2. @工程师提供办公建议，注入执行前断线，检查同一决策模式选择替补并完成交付。
3. 项目组先向真人澄清范围，脚本回复确认，再检查工程建议、审阅验收、leader 汇总全部完成。

故障是显式注入，健康探测、计划、成员答复使用真实模型。真人输入由脚本模拟，不代表多人实测。Jev 的复杂计划可能回退到普通成员模型，报告单列回退次数，不把混合执行宣称为 Jev 独立完成。

## 本轮实测发现及修复

- 完整 JSON 计划曾超过旧的 20 秒协调期限。云端计划现在共享 40 秒总预算，包括格式修正；本地协调仍为 20 秒。实测模型响应速度会波动，不能保证首条回复在数秒内出现。
- 模型曾把 skip 与剩余成员排程混在一起；专用故障协议消除了这类冲突。
- 模型为未分配成员返回空字符串时，现在与 null 一样视为未使用字段，不为此重做完整决策。
- 模型曾把有明确顺序的报数规划为并行；收紧决策提示，并在真实脚本中严格核对成员发言顺序。
- 云端普通 LLM 的首次不回复决策由同一模型做简短意图复核，发现未回答的请求则修正原计划；没有用关键词直接改派成员。
- 替补完成后多余的故障复核曾把任务误停为等待真人，现已去除；相关回归用例让 leader 和替补为不同成员。
- 真人确认后的全量计划曾被上下文收件人字段缩短，现已保持完整协作排程。
- 个人参与和先开场标记冲突时拒绝并修正，避免截短报数名单。
- 澄清修复只读原请求与公开上下文，避免把决策输出格式说明再次传给提问成员。验收按完整回复核对汇总，允许一个回复拆成多个气泡。

运行命令：

```sh
npm test -- --maxWorkers=2
npm run typecheck
npm run build
npx esbuild scripts/group-policy-scenarios.ts --bundle --platform=node --format=esm --packages=external --outfile=out/group-policy-scenarios.mjs
NODE_USE_ENV_PROXY=1 DOUCHAT_LIVE_SCENARIOS=1 node_modules/.bin/electron out/group-policy-scenarios.mjs
```

仅运行单项可设置 `POLICY_MODEL` 和 `POLICY_SCENARIO`，对应报告的字段。`--probe` 单独检查两个模型连接及一个简单计划。QA 文件不进入应用打包。
