# 群调度验证记录

日期：2026-09-23。范围：桌面本地单账号、自己的云端 Agent、一个真人或全 Agent。

后续调整：游戏仅作为协作验收场景，已移除群聊中的游戏入口、成员选择和游戏面板，以及对应的两个界面测试。下文 515 项是移除前的完整验证记录；移除后类型检查、聊天面板 28 项测试与构建通过，游戏规则和脚本测试保留。

## 测试方法

- 协议与规则：Vitest 覆盖路由、顺序依赖、50 人群并发限制、私信隔离、信息投递不唤醒、Leader 接管、待真人确认、日志重放、重复行动、取消、成员退出、账号隔离、重启及故障暂停。
- 游戏状态机：两个游戏 × 真人参与/全 Agent × 100 个固定随机种子，共 400 局；验证终止、合法行动、隐藏信息投影与唯一事件 ID。
- 真实模型：通过开发版已经配置的 OpenRouter，使用 `xiaomi/mimo-v2.5` 扮演玩家/项目成员；Jev 使用 `typesafe/jev-1.13`。模型调用、调度、数据库、恢复机制均使用产品代码。
- 真人输入由脚本通过产品的 `gameAction` / `sendMessage` 路径提交，不是邀请了真实用户参加。每种真人游戏必须至少实际提交过一次行动，不能把真人首夜出局而从未操作视为覆盖成功。
- 测试数据库与联系人均为独立的合成数据。原开发账号只读取供应商配置；凭据仅在进程内解密，未写入测试报告。
- 项目协作要求产品、工程、测试依次提供实质内容，最后由项目经理汇总；真人参与版本必须先仅有一个 Agent 回合，提出具体问题并等待真人，再继续协作。聊天气泡与 Agent 回合分别计数。除自动断言外，逐份检查了公开聊天记录中的交付内容和范围。

## 发现并修复的问题

1. 可选思考输出消耗预算，游戏模型发生超时。决策/游戏调用读取 OpenRouter 模型元数据，对可关闭思考的模型关闭思考，对强制思考模型保留低档位。
2. 仅凭 `leaderFirst` 停止监督，会在开场后丢失最终汇总。现在开场后仍监督，顺序计划可包含具体交付要求，汇总为明确终止步骤。
3. 真人回答澄清问题后，后续模型丢失原任务范围。持久化 `waiting` 状态与原任务，新输入恢复原要求和参与成员。
4. 可选 JSON 字段缺失或把真人当成 Agent 接收者，导致路由失败。自定义决策模型明确输出等待标志，有限修正错误字段，并校验成员与触发消息可见性。
5. 初轮 20 局真实游戏中，16 局自动完成，4 局暂停：3 局连续非法投票，1 局模型服务/输出异常。完善了开局声明的跳过/弃权机制；持续服务故障或连续三个无效槽仍暂停。
6. 平票随机选择曾在查找回调中重复取随机数，固定种子测试发现后改为只选一次 ID，再查找玩家。
7. 重启、成员退出、清空历史或取消时，迟到结果可能被提交。新增状态版本和原始消息存在性校验；已提交步骤只重放，不重新调用模型/工具。
8. 外部工具可能已经执行后，私信格式错误或本地 Agent 中断，不再自动让替补重复外部操作，而是暂停核对。
9. 模型只私发成果却没有完成要求的群内交付。现在校验公开交付，允许一次仅使用公开上下文、无工具的补正；保密任务不会被强制公开，补正失败则暂停。
10. 真人检查点曾只输出问候，没有提出问题。现在要求实际问题，云端澄清回合禁用工具；补正仍未提出问题则暂停。三个模式均重新通过真人流程。
11. 已完成的协作仍调用决策模型，可能被错误判为等待真人。现在在已声明成员全部交付后执行明确的 Leader 汇总步骤并结束，汇总中的 @ 不会再次开启循环。
12. 单人路由被无关成员的任务备注触发额外 Leader 回合。现在单个非 Leader 接收者默认只回复一次；系统保留 Leader 的 @ 派发记录，显式监督任务仍可继续。

## 结果

最新全量检查：**515 项测试通过，4 项按原配置跳过**；70 个测试文件通过、1 个跳过。`npm run typecheck`、`npm run build` 和 `git diff --check` 通过。400 局固定种子模拟包含在参数化测试中，不与 515 项重复相加。

第二轮真实游戏 **20/20 自动到达明确胜负**：每个游戏分别 5 局全 Agent、5 局含模拟真人。总计 429 次状态推进、32 次真人 API 行动，1 次非法模型行动按规则弃权。10 局含真人的游戏中，8 局实际发生真人行动；另 2 局真人提前出局，只计游戏完成，不计真人操作覆盖。

## 明确边界

- 这是固定变体的谁是卧底、六人简化狼人杀，不包含完整狼人杀角色集合。
- 云端模型仍可能暂时失败；有限重试后暂停是预期行为，不伪造玩家输出或游戏胜负。
- 游戏支持检查点恢复；普通任务中结果不明的外部操作、附件输入或成员/Leader 变化需要用户核对后重新发起指令。
- 未实现跨账号多真人游戏、分布式 Leader 租约、跨设备游戏私密投递。远程群继续使用原有协议。
- 已验证 React 组件交互和真实 Electron 运行时；原生界面自动化工具获取开发版窗口多次超时，尚未完成整窗视觉验收。
- 测试只能证明上述场景和故障路径，不等于任意开放式项目都能无误自主规划。
